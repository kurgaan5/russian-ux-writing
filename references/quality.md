# Приёмка и проверка качества

## Сначала смысл

Для каждого носителя проверь четыре слоя отдельно. **Язык:** орфография, грамматика, управление, согласование и пунктуация. **Смысл:** числа, даты, единицы, условия, отрицания, модальность, причинность и границы исследования. **Стиль:** канцелярит, пустые усилители, повторы, тяжёлые конструкции, неоправданные знаки и искусственные списки. **Носитель:** интерфейс поддерживает действие; страница объясняет; слайд передаёт тезис с основанием; отчёт сохраняет связную аргументацию и точные таблицы. Успех одного слоя не компенсирует провал другого.

Редакторский вывод «по данным опроса» не становится автоматически доказанным научным выводом. Не утверждай, что «детектор нейросетевого текста» проверил авторство: отдельного такого инструмента и надёжного критерия у скилла нет. Читай [formats.md](formats.md) для нужного носителя.

Сверь исходник, контекст и результат. Выпиши изменившиеся суммы, даты, единицы, интервалы, условия, отрицания, модальность, субъект, стадию и область данных. Такая сверка нужна и тогда, когда фраза выглядит безупречной.

Если известные факты конфликтуют, не выбирай удобный молча. Покажи противоречие и сформулируй конкретный вопрос. До ответа можно подготовить части, которые от него не зависят.

## Рубрика редакторской оценки

Для каждого применимого критерия поставь «пройден», «исправить» или «не проверено» и кратко назови основание. «Не применимо» используй, когда свойства действительно нет в задаче, а не когда не удалось его проверить.

| Критерий | Что проверять |
| --- | --- |
| Фактическая верность | Условия, числа, даты, отрицания, степень уверенности и этап процесса сохранены |
| Естественный русский | Грамматика, управление, согласование, пунктуация; фраза звучит живо и без кальки |
| Ясность действия | Читатель понимает следствие нажатия и ближайший доступный шаг |
| Достаточная краткость | Нет лишнего, но остались важные условия и нужный контекст |
| Терминология и тон | Одна сущность названа одинаково; стиль уместен ситуации и продукту |
| Состояние и доступность | Нет подмены ошибки пустотой, неизвестного нулём; важное не зависит только от цвета, места или плейсхолдера |
| Локализация и ограничения | Ключи/переменные сохранены; формы чисел, даты, формат и заданный лимит проверены |
| Контекст и границы | Рабочая область соблюдена; соседние состояния и момент раскрытия условий учтены |
| Необходимость правки | Замена устраняет конкретный дефект; приемлемый вариант не выдан за ошибку |
| Читаемость блока | Строки понятны с первого прочтения, звучат естественно и не дублируют соседние |
| Текст в макете | Проверены реальные ширина, шрифт и переносы либо явно указан непроверенный статус |

Смысловая ошибка блокирует приёмку, даже если остальные критерии пройдены. Нельзя компенсировать выдуманный возврат денег красивым стилем или средним баллом.

## Три вида проверки

**Автоматическая:** синтаксис JSON/YAML, сохранность известных ключей/переменных, заданные лимиты и конкретные неизменяемые значения. Сообщай, что именно проверил. Проверка наличия числа не доказывает, что оно относится к правильной сущности.

**Редакторская:** смысл, естественность, однозначность, интонация и пригодность к сценарию. Если её проводит тот же автор, называй это самопроверкой. Фиксированный балл или список слов не доказывает качество русского.

**Проверка интерфейса и пользователей:** ширина, переносы, реальные подстановки, объявление вспомогательными технологиями и понимание людьми. Без соответствующих наблюдений этот уровень остаётся непроверенным. По скриншоту нельзя утверждать работоспособность screen reader, а по тексту — соответствие всего продукта WCAG.

## Пакет строк для команды

Сохрани исходный формат, когда это возможно. Для отдельной таблицы полезны поля: ID/элемент, условие показа, финальный текст, доступное действие и вопросы к продукту. Не перегружай маленькую задачу формальной документацией.

При нескольких состояниях явно различай: данные ещё не создавались; поиск дал ноль; идёт загрузка; загрузка не удалась; часть данных отсутствует; доступ ограничен; успех подтверждён. Проходи только состояния, относящиеся к заданному сценарию.

## Как улучшать сам скилл

Используй реалистичные синтетические задачи с исходными фактами. Набор для улучшений отделяй от новых проверочных задач. После исправления инструкции проверь свежие примеры; если они выявили проблему и использованы для следующей правки, они больше не считаются отложенными.

Сохраняй входной контекст, исходный текст, получившийся текст, результат автоматических проверок, редакторскую оценку и причину. При сравнении версий оценивай поведение и смысл, а не совпадение с единственной «эталонной» фразой.

Минимально полезное покрытие: двусмысленное действие; ошибка с реальным восстановлением; пустой поиск; отсутствие доступа; платёж с неизвестным статусом; условный возврат; частичные данные; неизвестный счётчик; числительные; дата с поясом; ограничение длины; удачная строка без необходимости правки.

Для контекстного ревью добавляй ситуации: привычный аудитории термин уже принят в продукте; описательный заголовок не нуждается в замене; подпись дублирует заголовок; полное значение раскрывается перед подтверждением; точная длинная строка не помещается; грамматическая ошибка находится вне области задания; таблица и обводки должны ссылаться на одинаковые записи. Оценивай решения по контексту, а не совпадению с единственной эталонной строкой.

Не называй синтетическую самопроверку независимым тестированием или реальным пользовательским исследованием. Для рабочей готовности конкретного продукта нужны его факты, терминология и контекст. Критерий улучшения — отсутствие выявленных смысловых потерь и повышение ясности на новых задачах; абсолютное «лучше всех» не проверяется таким набором.
